# 对齐什么？重新思考 MiniMax M2 的智能体泛化

社区对新模型 [MiniMax M2](https://huggingface.co/MiniMaxAI/MiniMax-M2) 的关注令人兴奋，许多人称赞它处理复杂智能体任务的能力。作者的后训练工作主要关注智能体对齐，因此本文分享相关经验。

## 智能体对齐的真正问题：基准还是现实？

同一模型在一个框架中可能表现惊艳，在另一个框架中却几乎不可用。智能体可能在工具使用排行榜上得分很高，却在简单的真实任务中失败。基准表现与实际可用性之间的差距，是该领域的重要挑战。

设计 M2 时，团队同时追求两个有时会冲突的目标：

1. **在开源基准上表现出色**：基准可以测量“纯粹”能力。例如 BrowseComp 测试复杂搜索能力。用户很少会提出“找出第 n 位作者姓名中第三个字母为 x 的论文”这种刻意设计的问题，但能解决它说明模型具备较强基础能力。
2. **可靠地泛化到现实世界**：模型需要在陌生工具、IDE/命令行界面、智能体脚手架和用户环境中稳定工作，不能只擅长一种场景。

答案是两者兼顾：基准帮助训练技能，但最终必须确保这些技能在用户的实际环境中也能使用。

本文重点讨论更困难的问题：如何训练能适应真实环境的智能体？

## 为什么需要交错思考

项目早期，智能体表现不稳定，团队难以定位原因。经过讨论，尤其是与 Junxian He 教授和 Wenhu Chen 交流后，团队得出第一个重要结论：智能体需要交错思考。

这意味着智能体的内部推理可以在任务的任意阶段发生，而不是像标准推理模型那样只在开头思考一次。原因有二：

1. **保持长任务中的专注**：复杂智能体任务上下文很长，开头的一次思考不足以维持指令遵循和行为连贯。
2. **适应外部扰动**：工具输出会持续带来不可预测的信息。模型必须稳健处理变化、诊断错误并提取有用信息；持续推理使模型能够重新评估并适应环境。

这一原则成为 M2 效果的重要基础。

> **给 M2 用户的建议**：M2 将上下文作为记忆。为了获得更好效果，应保留完整会话历史，包括思考步骤。社区报告的表现差距，很多来自意外丢弃了这部分关键上下文；这在较简单的推理模型使用方式中较常见。

## 真正的泛化是适应扰动

团队最初认为，增加工具种类就能带来智能体泛化。

他们从 Python 解释器、搜索引擎和浏览器等少数工具开始，建立工具调用基线，再逐渐扩大工具数量和种类，希望智能体自然适应未见过的工具。

起初基准分数提升了，但团队发现问题方向不对：模型通过了测试，却在更换运行框架等轻微环境变化后表现骤降，距离“实际有用”仍很远。

更重要的结论是：**智能体泛化不只是适应新工具，而是要适应其整个运行空间中的扰动。**

![智能体任务运行空间中的扰动示意图](https://filecdn.minimax.chat/public/3b580365-f77b-4a06-9c8c-d7a3e1e9676a.jpeg)

一个智能体任务中可能发生变化的内容包括：

- 工具信息和可用工具集合。
- 定义智能体角色和规则的系统提示词。
- 用户提示词和具体目标。
- 文件、代码库、API 等运行环境。
- 每一步返回的工具结果。

旧的“扩大工具规模”方法只处理第一项，忽略了任务其他部分的变化。基于这一认识，团队构建了用于训练“完整轨迹泛化”的数据流程，使模型能适应每一步可能出现的变化。内部测试中，即使使用团队很少考虑过的陌生脚手架，M2 的表现也超出预期；工具调用和指令遵循能力都能良好泛化。

## 后续方向

M2 的研究让团队更了解智能体、泛化和数据，但也提出了更多问题。许多想法仍在探索中，团队计划继续研究这些方向，并开发更强、更实用的模型。
